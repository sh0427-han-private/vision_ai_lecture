## 1. 목표에 대한 종합 결론

**한 줄 평:** 사진이 중요하고 어려운 이유→Task 선택→CNN 계산→CNN 학습→데이터 일반화→평가까지 주된 인과 순서는 연결된다. “어떤 모델/Label로 과제를 시작하나?”와 CNN의 Gradient가 어디에 적용되는지를 설명하는 연결부가 이전보다 분명해졌다. 다만 정보 밀도와 리허설 분량은 화면 실측 없이는 완성으로 볼 수 없다.

| 사용자의 질문 | 현재 강의에서 답하는 지점 | 진단 |
|---|---|---|
| 그래서 **왜** Vision AI가 중요한가? | I3 제조 검사·안전/공간·영역 분석 활용 | 신규 반영. 실제 상용 성능/운영 사례로 혼동하지 않는 표기 유지 |
| 왜 어려운가? | I9–12 조명/회전/가림/중요 결함 → **I13 요약** | 신규 연결. 같은 생성 원본의 화면상 변형임을 명시 |
| 지금 어디까지 발전했고 종류가 뭔가? | C1–5 규칙→지도학습→사전학습, Class/Box/Mask/Anomaly | 신규 반영. SAM2/YOLO 모델 계열과 Task 개념 구분 |
| 과제를 하려면 어떤 Model/Data를 고르나? | C4–5 선택 경로, Model/Label 형태 → C20–24 데이터 조건·분할 | 학습 전 필요 정보가 모인다. C5는 글자 과밀 가능성 |
| CNN 학습 Architecture는? | C10 전체→C25–26 Loss의 의미→**C27 Forward/Backward Figure**→C28 Training/Inference | 큰 개선. 실제 렌더 화살표·글자 QA 필수 |
| 개념 전체가 부자연스럽지 않나? | 54장 세부 아래 + 2시간 시간표 | 큰 순서는 유효. 전환 2곳과 5분 회수 보완 필요 |

**개념적 엄밀성:** C3의 SAM 2는 promptable **이미지/영상 Mask 예측** 사례이지 새 산업 결함의 분류 정답을 자동 아는 모델이 아니다. C5의 Anomaly Detection은 정상 데이터 중심 학습이 가능한 모델 계열이지만 모든 방법에 동일한 Label 조건이 적용되지 않는다. CNN 이외 Transformer 기반 모델도 현재 사용된다. C27의 역전파는 **학습 대상으로 지정된 Weight**에만 적용되며 Freeze 설정이면 해당 Backbone은 갱신하지 않는다.

## 2. 추천 발표자 스토리라인과 문장

1. **I1→I3** “사과의 작은 결함을 찾아야 하는 상황을 생각합시다. 한 제품이 아니라 수많은 사진을 반복 확인한다면, 시각 AI가 도움을 줄 수 있습니다.”
2. **I3→I4–8** “이런 검사와 인식이 사람에게는 자연스럽지만, 모델이 실제로 받는 것은 사과라는 말이 아닌 Pixel 숫자입니다.”
3. **I8→I13** “숫자만 비교하면 조명/회전/가림 때문에 같은 사과가 달라 보입니다. 중요한 결함은 따로 찾아야 합니다.”
4. **I13→C1–5** “그럼 모델에게 정확히 무엇을 찾아달라고 해야 할까요? 유무가 필요한지, 위치가 필요한지부터 결정하면 정답 Label과 모델도 정해집니다.”
5. **C5→C6–10** “과제를 정했으니 이미지 모델 안의 가장 기본적인 계산부터 보고, 왜 CNN이 작은 영역을 사용하는지 연결하겠습니다.”
6. **C10→C11–19** “이제 전체 구조의 Kernel·Feature Map·Head 중 어떤 부분을 확대해서 보고 있는지 그림에서 따라가겠습니다.”
7. **C19→C20–24** “구조를 알았으니 학습에 넣을 사진을 준비할 때 무엇을 주의해야 할까요? 밝기 조건과 데이터 분리입니다.”
8. **C24→C25–28** “데이터와 Label을 마련했을 때, Loss가 알려주는 방향으로 실제 CNN Kernel이 어떻게 수정되는지 봅시다.”
9. **C31→C32–36** “학습 Loss가 줄어도 새 사진에서 놓친 결함이 있을 수 있습니다. 유무의 성능과 영역의 성능은 서로 다르게 확인합니다.”
10. **C36→C37–41** “처음 사과 사진으로 돌아가, 내 모델의 출력이 왜 맞다고 믿을 수 있는지 설명해 봅시다.”

| **C-40** | 실패 사진이 알려 주는 것 | 어둡고 작은 결함/배경 편향 실패 예시. 개념 가설과 실측 모델 실패를 혼동하지 않음 | 유지 |
| **C-41** | Vision AI 원리 · 무엇을 설명할 수 있나? | 사과 원본으로 돌아가 Input/Feature/Learning/Evaluation 네 질문, 유무에서 Mask가 필요한 경우 복습 | P1 · 5장·5분 마무리 시간 리허설 |

## 4. 아직 고칠 필요가 있는 사항 · 우선순위와 완료 판정

### P0 · 신규 그림이 실제 발표화면에서 읽히는지

- [ ] **C-05 (Task·Model·Label 매핑):** 4열에 각각 이미지·Model Family·Label 예시가 들어가 있다. 1366×768에서 **최소 글자 크기와 각 이미지 크기**를 실제 캡처로 확인한다. 과밀하면 Anomaly를 별도 응용/주석으로 줄이고 Classification/Detection/Segmentation 3개 결과를 크게 우선한다. **완료**: 역할·Model·Label 세 축을 학생이 10초 안에 찾을 수 있고 겹침 없음.
- [ ] **C-27 (CNN 학습 Architecture):** `lecture_cnn_training_feedback_ko.svg`의 RGB 사진·Kernel·Feature Map·Task Head와 Loss/Gradient의 두 방향 화살표를 1920×1080, 1366×768에서 확인. Arrow가 가중치 갱신 대상에 실제로 연결되고, Freeze 시 예외가 텍스트에 남아 있는지 점검. **완료**: Forward/Backward 각 경로를 가리키며 Loss가 어디에서 만들어지고 무엇이 갱신되는지 설명 가능.
- [ ] **I-03 / I-13:** 3~4열 사진의 원본 비율·크롭·생성 변환 정확성·외부 원근감 사진 출처를 확인. I13의 어두움/회전/가림이 **동일 사과 이미지**임을 보여주되 조명·시점 실제 재촬영으로 오인되지 않도록 한다.
- [ ] **전체 54장**·두 Viewport = **108개 화면**의 텍스트 잘림/축소/그림 경계·브라우저 콘솔 검사 및 54장 목차/키보드/기존 인터랙션 확인.

### P1 · 흐름과 사례를 더 다듬을 부분

- [ ] **I-09–13 · 반복 방지:** 변화 예시 9·10, 사과 다양성 11, 판단 기준 12, 종합 13의 발표 원고가 서로 같은 문장을 반복하지 않도록 구간별 “Pixel 변화 / Label 유지 / 검사 목적 / 종합”의 역할을 분리한다. I13은 1분 이내의 요약·C1 질문 전환으로 사용.
- [ ] **I-03 · ‘왜 중요?’ 실사 보강:** 현재 제조(사과)·장면 이해(회랑)·정밀 영역(사과 Mask)은 **가능한 활용 형태의 개념 예시**다. 실제 의료/생산라인/교통에 도입된 시스템의 성능으로 오인되지 않게 유지하고, 다른 산업 실사 사진을 직접 추가하는 경우 그 그림 옆에 출처를 남긴다.
- [ ] **C-02–05 · 같은 이야기 다른 목적:** C2 규칙 vs 학습은 ‘왜 배우나’, C3 발전 단계는 ‘현재 활용 가능한 접근’, C4는 ‘기존 모델을 먼저 시험할지’, C5는 ‘정답 데이터의 형태’를 각각 단 하나의 중심 메시지로 유지. 뒤로 갈수록 규칙 설명을 다시 반복하지 않는다.
- [ ] **C-22 · Group Split의 관련성:** 사과 결함 사진이 동영상이 아니라도 같은 사과를 연사·여러 각도에서 촬영한 샘플은 그룹으로 묶어야 할 수 있다. ‘영상 A/B/C’의 묶음이 사과 개체/촬영 세션에 어떻게 대응하는지 한 문장 추가.
- [ ] **C-36 · 지표 전환:** C32–35의 분류 혼동행렬/Recall에서 C36의 IoU로 넘어갈 때 “결함의 *유무*만 판정하면 Recall, *위치*가 필요하면 Box/Mask의 겹침도 본다”는 문장을 앞뒤 부제 중 한 곳에 넣는다.
- [ ] **C-37–41 · 회고 5분:** 교재 5장을 5분에 끝내는 데 문제가 없는지 리허설한다. C39 임계값 조작을 라이브 시연할 경우 다른 복습 장표 설명을 줄이거나 별도 Q&A 시간을 배정한다.
- [ ] **C-18 / C-23–24 · 사과→강아지 예시:** SqueezeNet의 공개 실측 그림과 전처리·증강 계산을 재사용하려는 목적이다. 수강생이 ‘사과와 강아지 모델이 같은가?’로 혼동하지 않도록 이미지 옆에 실제/생성/개념 타입 표시를 유지한다.

### P2 · 교육용 수치·용어의 오해 방지

- [ ] RGB 채널값 수와 Pixel 수의 단위를 섞지 않기. C11–12의 5×5 Kernel 숫자는 사과 JPEG에서 실제 추출한 값이 아님.
- [ ] C13 공유 가중치 9/9216/1048576 비교의 연산 조건을 유지하며 세 구현의 표현력이 같은 것으로 단정하지 않기.
- [ ] C20 Dataset의 두 원본 생성 사과를 실제 동일 개체 촬영·검사 실측으로 소개하지 않기.
- [ ] C25–26의 x=2,y=4 회귀를 실제 CNN 분류 Loss로 소개하지 않기.
- [ ] C39 Threshold 교육용 100건은 Validation 예시이고 독립 Test 실측 결과가 아님; `TP18/FN2/FP4/TN76` 기준 0.50 데이터 동기화 유지.
