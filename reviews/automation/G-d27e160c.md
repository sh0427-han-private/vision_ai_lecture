## 3. Issue 목록과 재검증 기준

### G-01 — Major / Builder — OPEN: P48 고정 점수 분포의 승인 Figure 명세 불일치

- **위치:** `docs/project_course.js:6–10` (Score 배열), `:22–44` (histogram 축), `docs/vision_ai_course.html:179` (P48 Figure)
- **기대(승인 스토리보드 P48 고품질 Figure 추가 인수조건):** 실제 불량 `0.8×11, 0.6×7, 0.4×2`; 실제 정상 `0.8×2, 0.6×2, 0.4×26, 0.2×50`인 **정확히 한 개의 100건 배열**을 분포·수치의 공통 출처로 사용할 것.
- **관찰:** 현재 코드는 0.60..0.855 등 연속된 점수를 사용하고 정상 점수 76개를 0.10..0.40에 분산함. 결과 TP/FN/FP/TN은 의도 수치에 맞지만, 분포 그림은 승인된 0.2 중심 정상 50건/0.4 중심 정상26건 등의 실제 모양을 표현하지 못함. 현재 histogram은 y 눈금 0–30(`unit=4.7`)으로 하드코딩되어 있어 지정 분포(한 bin에 50건)를 그대로 적용하면 막대가 차트 밖으로 나감.
- **영향:** 학생이 실습의 입력 데이터 분포와 임계값 간 연결을 승인된 예제로 재현할 수 없고, Figure의 데이터 출처와 인수조건이 불일치. **잘못된 혼동행렬 수치로 판정하지 않음**.
- **수정 방법:** JS `scores`를 스토리보드의 정확한 `(score,label)` 100건으로 교체; `bins`/threshold/matrix/FN·FP/Precision·Recall은 같은 배열에서 파생 유지. y축 눈금/막대 unit을 최대 bin count 50 이상에 맞게 동적 또는 0–50 이상으로 재설계. 히스토그램과 Table을 별도 하드코딩하지 말 것.
- **재검증:** 100개 `score,label`의 빈도표가 승인 구성과 정확히 동일, 세 threshold 전부 위 100건 표와 동일, select/Reset/키보드 조작마다 histogram threshold 위치·표·막대·지표 동기화. 1920×1080/1366×768에서 최대 50건 막대가 잘리거나 Label이 겹치지 않는 캡처와 DOM assertion 제공.
