## 1. 종합 판단

**판정: 핵심 소재는 적절하지만, 현 순서 그대로는 '끊김 없이 이어지는 입문 강의'로 완성되었다고 보기 어렵다.**

### 잘되어 있는 부분 — 우선 보존

1. **Intro 3–9:** 사과 사진 → 실제 Grayscale/RGB 숫자 → 해상도 → 조명·변형으로 이어진다. Vision의 어려움을 '숫자로부터 의미를 찾아야 한다'는 문제로 설명하는 접근은 좋다.
2. **Intro 11 → 통합 1:** 픽셀 변화의 크기보다 결함 판정에 필요한 차이가 중요하다는 메시지에서, 분류/검출/분할의 **서로 다른 출력 요구사항**으로 연결하기 좋다.
3. **통합 7–10:** 퍼셉트론 → AND/XOR → ReLU → 다층 비선형성의 의도가 분명하다. 단, ReLU가 XOR를 해결하는 구체적 과정과 '직선 층의 한계'를 과도한 수식 없이 연결해야 한다.
4. **통합 11–21:** CNN 전체 구조를 먼저 놓고 Kernel → Feature Map → 공유/채널/크기 → 실제 모델 반응 → Backbone/Head로 가는 내부 설명 순서는 대체로 적절하다.
5. **통합 23–25, 30–34:** 독립 분할·전이학습, 임계값·혼동행렬·Precision/Recall·IoU를 각각 실제 의사결정과 연결할 수 있다. 100건 예시는 여러 장에서 공통으로 쓰므로 유지할 가치가 높다.
6. **통합 35–39:** 같은 사과 결함 사례로 AI 의뢰 → 결과 재집계 → 실패 분석 → 완료 기준까지 돌아오는 결말 자체는 교육 목표에 부합한다.

### 검토 결론에 따른 작업 원칙

- 초보자의 이해를 위해 **내용을 더 길게 쓰기보다** 시각적 단계와 선행 맥락을 보충한다.
- 각 장을 읽고 **입력은 무엇인가 → 무엇을 하는가 → 어디에 쓰는가**를 답할 수 있어야 한다.
- 기술적으로 필수인 전문 용어만 첫 등장 시 풀어 쓰고, 다음 장부터 같은 한국어 용어를 유지한다.
- 실물 사진·계산된 Feature Map·강의용 개념도·실제 모델 예측은 **서로 다른 증거 수준**이다. 구분 표기한다.
- **기존 슬라이드 제목/부제/중앙 그림/하단 한 줄 정리 구조를 유지**한다. 새 설명이 필요하면 장을 조정하거나 시각화하지, 발표자가 외워야 할 긴 원고를 넣지 않는다.

## 2. 추천하는 전체 스토리라인

> **한 문장 중심 질문: "카메라가 찍은 사과 사진에서 작은 결함을 놓치지 않으려면, AI에 무엇을 알려주고 결과를 어떻게 확인할까?"**

| 장면 | 초보자의 질문 | 이어서 알려줄 개념 | 강의가 얻는 답 |
|---|---|---|---|
| ① 사진을 본다 | 컴퓨터는 왜 사과를 바로 이해하지 못할까? | Pixel·RGB·배열·해상도 | 컴퓨터 입력은 숫자이며 작은 결함 정보가 축소로 사라질 수 있다. |
| ② 조건이 바뀐다 | 같은 사과인데 왜 매번 다르게 보일까? | 조명·회전·가림·일반화 | 무관한 변화와 필요한 결함 차이를 구분해야 한다. |
| ③ 무엇을 찾아야 하나 | 결함의 유무, 위치, 모양 중 무엇이 필요할까? | Classification·Detection·Segmentation·Label | **목표 출력**이 먼저이며 정답 형태가 따라온다. |
| ④ 규칙이 통하지 않는다 | 모든 사진에 쓸 단일 기준을 사람이 작성할 수 있을까? | 규칙 기반 vs 학습, 신경망·비선형성 | 여러 예시에서 판단 기준을 배운다. |
| ⑤ 사진을 학습한다 | 작은 얼룩·경계를 어떻게 찾을까? | CNN·Kernel·Feature Map·Channel·Head | 좁은 영역에서 찾은 패턴을 여러 곳에서 재사용한다. |
| ⑥ 어떻게 배우고 검증하나 | 어느 숫자를 고치고, 무엇을 믿을 수 있을까? | Loss·학습/추론·데이터 분리·전처리·전이학습 | 정답으로 가중치를 조정하되 독립 데이터로 확인한다. |
| ⑦ 성능을 판정한다 | 95%가 맞았다고 작은 결함도 놓치지 않을까? | Threshold·Confusion Matrix·Recall·IoU | 실패 유형과 과제별 지표를 선택한다. |
| ⑧ 첫 프로젝트 | 그럼 AI에게 무슨 일을 시키고 뭘 확인해야 할까? | 작업 명세·오류 분석·재현·운영 | AI는 구현을 도와도 **문제 정의와 검증 책임**은 사람에게 남는다. |

**추천 최소 재배치(현 번호를 식별자로 사용, 실제 번호는 구현 때 다시 부여):**

- Intro `1–11`은 큰 구조 유지.
- 통합 **`1–3 → 7–10 → 11–19 → 21`**: 무엇을 만들지 → 신경망의 한계 → CNN 계산 → Backbone/Head.
- 이어서 **`22–24 → 28–29`**: 어떤 사진·Label로 학습하는지, 겹치지 않게 나누기, 입력 규격과 증강.
- 이어서 **`4–6 → 20 → 25–27`**: 이제 *학습할 가중치*를 본 상태에서 Loss·갱신·학습/추론 → Kernel 학습 → 전이학습·로그·일반화.
- 마지막 **`30–34 → 35–39`**: 판정 점수·평가 → AI 작업·재검증.
- **전체 50장 범위는 우선 유지**, 내용 중복과 발표 밀도를 살펴 필요하면 압축/분할한다. 위 순서는 **제안**이며 실제 적용 때 현재 번호·목차·딥링크·시간표를 모두 재계산해야 한다. 통합 3에서 Transfer Learning 명칭을 너무 자세히 정의하지 않는다.

## 3. 슬라이드 50장 상세 내용 검토

표의 **유지**는 유용한 개념·위치를 지킨다는 의미이지, 문구와 그림의 완성도를 보증한다는 뜻이 아니다. P0/P1/P2는 수정 우선순위.

### A. Intro — 11장

| 현 번호 · 제목 | 왜 필요한가 / 어디에 사용되는가 | 판단 · 구체적 보완 |
|---|---|---|
| **I-01 AI와 시각의 출발점** | 수업 전체의 공통 과제와 도착점을 약속. | **P1** 슬라이드 부제가 목표 세 가지(분류·검출·분할, AI 협업, 요구사항)를 한꺼번에 열거한다. '사진에서 작은 결함을 찾는 AI는 어떻게 작동할까?' 중심 질문 하나만 전면 배치. |
| **I-02 사람의 시각 · 장면 이해** | 사람이 사진에서 무엇/어디를 바로 알아보는 출발점. | **유지/P2** 회랑의 공간 깊이를 보는 사진은 좋지만 이후 사과 분류와 연결 문장 필요: '사과의 모양과 위치도 우리는 쉽게 알아본다'. 3D 복원 강의처럼 보이지 않게 범위를 한정. |
| **I-03 사람의 의미 인식 vs Pixel 숫자** | 사람은 의미, 컴퓨터는 이미지 값이라는 대비. 이후 모든 모델 입력의 근거. | **유지** 'AI는 숫자밖에 모른다'라는 과장 대신 '입력에는 사과라는 정답이 직접 쓰여 있지 않다'를 반복. 12×8 Grayscale은 **교육용 축소**라고 유지. |
| **I-04 사진에서 밝기 숫자로** | Pixel과 0–255, 같은 위치의 사진↔수치 대응. | **유지/P1** 대상을 클릭할 때 같은 6×6 영역이 숫자·밝기로 바뀌는 핵심 실습. 회귀식·Grayscale 변환식 암기는 불필요. 선택한 영역의 좌표/숫자 정확성만 검증. |
| **I-05 RGB · Pixel당 세 숫자** | 실제 컬러 입력은 한 위치에서 3개 값을 갖는다는 교정. | **유지** 04의 Grayscale과 다르다는 질문을 받아 자연스럽게 전개. R/G/B가 서로 다른 채널인지 실제 클릭 예시 유지. |
| **I-06 RGB 이미지와 숫자 배열** | H×W×3과 Pixel 수 vs 채널 값 수 구분. | **유지/P2** `640×960×3=1,843,200`은 정확한 숫자 **데이터 개수**이지 Pixel 수 아님. 이 숫자가 커서 CNN의 효율적 처리 필요하다는 후속 연결을 보강. |
| **I-07 해상도에 따른 정보 차이** | 작은 결함이 다운스케일 때 남는지 → 모델 입력 크기 선택. | **P1** '정보가 더 많다'를 절대 화질 개선처럼 말하지 말고 **동일 원본을 낮은 해상도로 만들 때 세부가 줄어든다**로 한정. 후반 전처리 28에 직접 연결. |
| **I-08 조명·색감에 따른 Pixel 변화** | 같은 정답인데 숫자가 바뀌는 환경 변동. 일반화·증강의 필요성. | **유지** 화면 필터 예시이지 실제 촬영 실험이 아님을 유지. '학습할 때 이런 상황도 고려'를 이후 데이터 22/증강 29에 재연결. |
| **I-09 회전·크기·가림·흐림에 따른 변화** | 시점/가림/초점 때문에 숫자 배열이 달라짐. | **P1** 크롭 확대와 회전은 실제 3D 시점 변경과 다름. 용어 정확히 쓰고 '가림으로 결함 자체가 사라지면 복구 보장은 없다'는 한계 추가. |
| **I-10 다르게 생겨도 같은 종류** | 클래스 안 다양성(intra-class variation)과 한 대상 이름 학습. | **P1** 의자가 갑자기 나오는 이유가 불명확. '사과도 색·품종·형태가 달라도 같은 사과'를 먼저 보여주고 의자는 필요 시 보조 사례. **같은 클래스**와 **정상/불량**은 서로 다른 판정 기준임을 구분. |
| **I-11 큰 변화보다 중요한 차이** | 무관한 밝기 변화 vs 중요한 작은 결함; Task·Label 전환용 마지막 다리. | **P0** 균열된 표면에서 사과 반점으로 돌아갈 때 논리 전환 필요. '검사 기준을 정해야 비로소 중요한 변화가 결정된다' → 통합 1의 세 Task로 **직접 연결**. Intro 마지막 장으로서 핵심 통찰 한 문장으로 압축. |

| **C-08 AND와 XOR · 직선으로 구분할 수 있을까?** | 가중합+단일 판정선의 한계 → 활성화 함수의 필요성. | **P1** 진리표+좌표를 둘 다 암기시키지 않는다. AND는 직선 한 개로 구별, XOR는 불가를 **같은 축**에서 보여주고 '그래서 계산을 여러 번 꺾어야 한다'로 연결. XOR의 존재 이유를 잃지 말 것. |
| **C-09 ReLU · 비선형성의 시작** | 입력 구간마다 다른 반응을 만들어 단일 직선 한계 탈피. | **유지/P1** 현재 직선 vs 꺾인 선의 대비는 좋음. **ReLU 하나가 XOR를 자동 해결한다**는 인상을 피하고 '여러 뉴런·여러 층에 조합하면'이라고 한정. |
| **C-10 신경망의 핵심 · 계산 사이의 비선형성** | 많은 Affine층만 겹쳐도 새 결정 경계가 생기지 않는 이유. | **P1** 수식 `W₂ReLU(W₁x+b₁)+b₂` 자체보다 같은 입력을 두 경로에 넣어 **직선만 vs 꺾이는 경로**를 시각 대비. '선형층 합성=단일 Affine 변환' 용어는 엄밀하게 유지. |
| **C-11 CNN 전체 구조 · 특징에서 판정까지** | 이제 숫자 배열에 신경망을 적용. CNN 세부 슬라이드의 지도가 됨. | **P0/강화** 현재 4개 텍스트 박스만으로는 **CNN 아키텍처**의 형태가 안 보인다. 사진→여러 Feature Map stack→작아지는 공간 크기→Head→판정의 전문적 단면 Figure로. 각 블록에서 다음 12–21번이 설명할 부분을 가리킨다. |
| **C-12 Kernel · 작은 영역의 가중합** | 작은 패턴을 계산하는 도구의 정의. | **P1** 실제 사진의 3×3 영역을 먼저 표시하고 5×5 숫자·3×3 Kernel·결과 1개로 확대. 상관 연산과 수학적 Convolution 차이는 발표용 본문 핵심이 아닌 참고. Kernel이 **검사 기준으로 학습되는 값**임을 예고. |
| **C-13 Feature Map · 같은 계산을 위치마다** | Kernel을 전 위치에 재사용 → 반응 지도. | **P1** C-12의 같은 배열·필터를 실제로 한 칸 움직여 `-6,12,…`를 출력 그림에 순서대로 채워 넣는다. '위치별 반응'이 원본 RGB 사진과 다른 데이터임을 분명히. |
| **C-14 CNN · 지역 연결과 가중치 공유** | CNN의 계산 효율·이동한 패턴 재인식의 원리. | **P1** 1,048,576/9,216/9 숫자 비교만으로는 왜 쓰는지 전달이 약함. **전체 연결 → 지역 연결 → 같은 Kernel 공유** 관계를 연결선으로 먼저 보인다. 수치 가정(1채널, 32×32, bias 제외) 유지. |
| **C-15 RGB 입력과 출력 Channel** | 필터 한 개가 R/G/B 전체를 보고 1개 Feature Map을 만들고, 여러 필터가 출력 채널이 됨. | **P1** 3개 입력 Plane → 3×3×3 Filter → 1개 Map, 서로 다른 필터 2개 → 2채널을 입체 그림으로. RGB와 Feature Channel이 서로 다른 의미임을 강조. |
| **C-16 Stride · 계산 위치의 간격** | 촘촘함과 계산량·위치 정보의 절충. | **유지/P1** C-12/13과 같은 5×5/3×3을 재사용하는 점 좋음. 출력 3×3↔2×2의 **칸 수와 위치 정보 변화**가 1순위, 출력 크기 수식은 2순위. |
| **C-17 Padding · 입력 바깥에 값 채우기** | 경계 위치에서 계산하고 출력 공간 크기를 조절. | **유지/P1** 입력·Kernel이 바뀌는 이유를 바로 표시. 3×3→1×1 vs 3×3→3×3 정확하나 'Padding이 물체 정보를 새로 만드는 것'이 아니라고 정리. |
| **C-18 Max Pooling · 영역별 최댓값** | 특정 지역의 강한 반응만 대표로 남겨 공간 축소. | **유지/P1** 4×4→2×2 계산은 정확. Kernel 가중합이 아니라 **채널별 고정 최댓값 연산**인 차이, 위치 세부 손실이 그림에 드러나야 한다. 모든 CNN에 필수는 아님. |
| **C-19 실제 Feature Map · CNN 내부 반응** | 앞에서 배운 숫자 지도가 실제 모델에서 어떻게 보이는지 증거. | **유지/P1** SqueezeNet1.1·ImageNet·강아지 실측 출력을 **실제 Feature Map 일부 채널**이라고 유지. 스테이지별 `H×W×C`는 전체 shape이고 보여 주는 이미지는 **4개 채널 샘플**이라는 구별 중요. '중간층=특정 의미의 물체' 같은 검증 안 된 단정 금지. |
| **C-20 학습 과정에서 바뀌는 Kernel** | 일반 학습 규칙을 CNN의 Kernel 가중치 갱신과 다시 결합. | **P1/이동** C-04/05 바로 뒤에 오면 '숫자 가중치를 왜 배웠나'가 자연스럽게 해결. 같은 입력에서도 학습 전/후 Feature Map·판정이 달라질 수 있다고 **개념적 변화**만 설명. |
| **C-21 Backbone과 Task Head** | CNN 공통 특징과 Task별 출력 분기. C-01 회수. | **유지/P1** C-19 뒤에 붙여 Backbone과 세 가지 Head를 대조하고, **한 모델이 세 출력 모두를 제공하는 것 아님** 명시. 1번의 사과 사진·같은 결함을 다시 사용하면 좋다. |
| **C-22 데이터셋 · 판정 기준과 촬영 조건** | 모델보다 데이터와 Label 기준이 실제 성능을 결정. | **P1** 텍스트 3패널 대신 동일 결함의 정상/불량·밝은/어두운 환경 예시. '결함처럼 보이는데 정상인 경계 사례'에서 라벨 기준 합의가 왜 중요한지 보여준다. |
| **C-23 Train · Validation · Test** | 학습·선택·최종 확인을 독립 분리. | **유지** 한 데이터셋의 세 가지 역할은 정확. 70/15/15는 예시이지 강제 비율이 아님; 같은 사과/촬영 묶음은 나누지 않도록 C-24로 연결. |
| **C-24 Video Group Split · 데이터 누출 방지** | 비슷한 연속 프레임이 학습과 시험에 섞이는 편향 방지. | **유지/P1** 비전공자에게 **'같은 사과 연사 사진을 시험지에 넣는 것'**이라는 비유를 먼저 설명. 새 사과가 목표면 사과 ID, 새 설비면 설비 ID 기준의 Group이 달라짐. |
| **C-25 전이학습 · 고정과 미세 조정** | 기존 CNN 특징을 재사용하여 적은 데이터로 새 결함 Task에 적응하는 선택지. | **유지/P1** C-03의 '기존 모델' 답을 회수. Freeze/Head 학습 vs Fine-tune 선택을 데이터 양·Validation 검증과 연결. **사전학습=현재 결함 정답 인식**은 아님. |
| **C-26 학습 로그 · Batch, Step, Epoch** | AI 도구가 반환하는 훈련 로그를 읽을 최소 용어. | **P1** 10장→4+4+2, 2Epoch→6Step은 가정하에 맞음. Hyperparameter 정의를 Batch 계산 앞에서 길게 늘이지 말고 '한 번에 몇 장을 보나?'와 실제 로그에 묶는다. Gradient 누적 시 Step 정의가 달라질 수 있음. |

| **C-28 Preprocessing · 입력 규격 맞추기** | 모델이 요구하는 이미지 크기·색·값 범위로 바꾸기. | **유지/P1** 강아지 정사각 강제 늘림 vs 비율 유지 Letterbox는 좋음. Intro 7 '작은 결함 축소 손실'을 다시 연결. 학습·추론 규격 일치를 하나의 결론으로. |
| **C-29 Data Augmentation · 조건 변화 만들기** | 학습에서 조명·각도·가림 변화를 경험하도록 돕기. | **유지/P1** Intro 8–9와 직접 연결. 결함을 없애는 변환은 Label을 틀리게 한다는 중요한 예외 유지. 먼저 Group Split 후 Train에서만 증강. |
| **C-30 Score Threshold · 판정 기준** | 모델 Score를 실제 불량/정상 경보로 바꾸는 운영 결정. | **유지/P1** Score `0.82`와 임계값 0.50/0.90은 개념적으로 맞음. **Score가 보정된 확률일 필요 없음**을 유지하고 C-31–33의 별도 100건과 구분. |
| **C-31 Confusion Matrix · 100건 평가** | 놓친 불량(FN)·오알람(FP)을 세기. | **유지** TP18/FN2/FP4/TN76 합계100, 정상80·불량20으로 일관됨. 이후 C-32/33과 숫자 연결을 지킬 것. |
| **C-32 Accuracy의 함정 · 모두 정상이라면?** | 불균형일 때 전체 정답률 하나로 성능을 평가할 수 없는 이유. | **유지/P1** '모두 정상' Accuracy80%지만 Recall0%의 대조 정확. 실제 불량 사진을 놓친 20개로 나타내면 표보다 직관적. |
| **C-33 Precision과 Recall** | 미검출 vs 과경보의 교환관계를 선택하는 기준. | **유지/P1** `18/22=81.8%`, `18/20=90%` 계산 맞음. 분모가 무엇인지 **사진 묶음/두 질문**으로 그림을 먼저 보여준다. |
| **C-34 IoU · 박스 겹침 비율** | 분류와 달리 검출/분할은 위치·영역도 맞아야 함. | **유지/P1** 같은 반점 Box의 정답 vs 예측으로 시작. IoU=겹친 영역/합친 영역, 0–1. mAP는 이름만 소개하고 계산 강의로 확장하지 않음. 분할 Mask에도 IoU 적용 가능. |
| **C-35 과제를 시작할 때 선택할 개념** | 전체 이론의 의사결정 지도로 회수. | **P0** 테이블은 맞지만 갑자기 업무 회의 문서처럼 보임. '사진→Task/Label→CNN/모델→데이터→평가→개선' **하나의 루프**를 보여준 뒤 5개 질문을 연결. |

## 5. 정확성·설명 밀도 관련 확인 사항

### 계산/정의 — 현재 표기 자체는 타당

- I-06: 640×960=614,400개 **Pixel 위치**, RGB 값은 3배인 **1,843,200개 숫자**.
- C-05: `ŷ=wx`, `x=2, y=4, w=0.5`, 제곱오차 9, Gradient -12, 학습률0.1→`w'=1.7`, 오차 0.36.
- C-08: AND `0.5x1+0.5x2-0.7`의 결정 경계는 `x1+x2=1.4`, XOR는 단일 직선으로 분리 불가.
- C-12/13/16: 5×5 데이터·3×3 가중치·Stride1 결과 3×3, Stride2 결과 2×2. `-6` 및 `12` 반응 계산 일관.
- C-17: 3×3 합계 Kernel, Padding0=45(1×1), ZeroPadding1=3×3 출력, 경계값 변함.
- C-18: 2×2 MaxPooling/Stride2는 4×4→2×2, 결과 `[[6,4],[7,9]]`.
- C-31–33/37: TP18, FN2, FP4, TN76 → Accuracy94%, Precision81.8%, Recall90%. 프로젝트의 0.50 예시와 일관.
- **단, 이는 저장소 HTML/JS에 명시된 정적 예시를 검토한 결과**이지 공개 브라우저의 계산 동작을 실행 검증했다는 뜻은 아니다.

### 정확성·오해 방지 — 보완하거나 그대로 지킬 것

1. **AI 입력=숫자**와 **AI는 의미를 절대 모른다**는 다른 주장. 모델은 학습 후 유용한 표현을 형성할 수 있다.
2. **Feature Map**은 CNN 층의 출력이고 **Kernel**은 가중치다. 'Feature Map을 필터가 학습한다'처럼 둘을 뒤집어 말하지 않는다.
3. **Stride/Pooling**은 공간 분해능 감소를 일으킬 수 있고, **Padding**은 경계 계산/출력 크기를 바꾼다. 무조건 정확도 상승이라고 주장하지 않는다.
4. 고전 Perceptron의 Step은 출력 함수이고 `Wx+b`는 판정 전 가중합이다. ReLU의 비선형성은 **여러 층과 조합**될 때 표현력을 높인다.
5. **Training과 Inference**는 목적이 다르다. 같은 전처리 규격은 유지되어야 하지만 Training에만 증강 적용하는 것이 기본이다.
6. 데이터 Label과 예측(Prediction)을 시각적으로 다르게 표시하며, Box/Mask 도식을 **실제 모델 결과**로 부르지 않는다.
7. Feature Map SqueezeNet 실측 그림과 외부 강아지 사진, 직접 만든 사과 결함 개념 그림의 데이터 출처/검증 범위를 분리한다.
8. Accuracy/Recall/Precision은 **분류·판정 수준** 예시; 검출·분할의 위치 성능은 IoU와 적절한 Task 지표가 필요하다.
9. Threshold 0.82가 **보정된 82% 확률**이라는 의미는 아니다. 실제 운영 임계값은 Validation에서 선정하고 Test에서는 고정한다.
10. 비전공 2시간 강의의 **주 목표는 계산값 암기가 아니라 상황별 개념 선택**이다. 불필요한 `backprop` 유도, K-Fold, 최신 모델 계보는 추가하지 않는다.

## 6. 2시간 강의 운영 검토

현 강의계획은 Intro 20분, Task·학습 15분, 신경망 15분, CNN 20분, 데이터·평가 25분, 프로젝트 15분, 질문 10분이다. **50장/110분 약 2.2분/장**이므로 클릭 실습과 청중 질문을 포함하면 실제 여유는 작다.

- **필수 체험 세 가지**: I-04 Pixel 클릭(숫자가 실제 바뀜), C-04 학습 전/후(오차 감소), C-37 Threshold 변경(FN/FP 교환). 실시간 설명시간 확보.
- C-07–18에서 **모든 산술을 칠판처럼 전개하지 않음**: 한 위치 Kernel 계산 1회 → 나머지는 반응 분포 그림으로 확인.
- C-30–34에서 서로 다른 평가 지표를 외우게 하지 말고 동일한 100건으로 3개 질문에 답하게 한다: "몇 개 놓쳤나?", "경보 중 진짜는 몇 개인가?", "박스는 얼마나 맞았나?"
- 외부 강아지 사진 실측 Feature Map의 **사과 결함 판정 성능을 보였다고 오해시키지 않음**.
- 프로젝트 파트가 강의 목표보다 과도한 비중을 차지할 경우 **C-35~39의 표 설명을 줄이고** C-11/19의 CNN 핵심 Figure 설명 시간을 확보한다. 추가 슬라이드로 총 시간을 무작정 늘리지 않는다.
