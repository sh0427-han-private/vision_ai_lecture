## 2. 전체 시각 디자인 시스템 — 변경 기준

강의 모든 페이지에서 **동일한 4단 구성**을 적용하되, 표지·체험형 슬라이드는 예외로 한다.

```text
┌──────────────────────────────────────────────────┐
│  [제목]  CNN · 작은 영역에서 특징 찾기             │
│  [부제]  커널 하나로 사진의 여러 위치를 살펴본다.   │
│                                                  │
│         실제 입력 사진 → 계산/변화 → 출력 결과    │
│              메인 그림(화면 중심 60~75%)          │
│                                                  │
│  [정리] 같은 규칙을 모든 위치에 적용해 반응 지도를 만든다. │
│  [외부 이미지를 쓴 경우에만] 출처: 기관 · 원문 링크  │
└──────────────────────────────────────────────────┘
```

- **제목:** 1줄 명사구, 구어체의 `~입니다` 금지. 최대한 짧게(예: '가중치 공유', 'RGB → Feature Channel'). 주제를 나열하지 말고 한 메시지.
- **부제:** 처음 접하는 사람에게 **'왜 이 그림을 봐야 하는지'**를 답하는 쉬운 한 문장. 인라인 영어/수식/단서를 세 개 이상 병렬 나열하지 않는다.
- **그림:** **왼쪽→오른쪽 입력·과정·출력** 또는 명확한 Before/After. 메인 그림이 차지하는 **시각 중심 영역 약 60–75% 권장**(강제 픽셀 비율 아님). 작은 장식 카드보다 하나의 큰 Figure가 우선.
- **정리:** 새로운 용어 추가나 반론 나열 대신 **'그래서 어디에 쓸까?'**에 답하는 한 문장. 예: 'Stride를 크게 하면 빨라지지만 작은 결함의 위치 단서가 줄 수 있다.'
- **이미지 선택:** 실제 현상은 실제 사진/검증된 영상처리 결과; 정확한 CNN 구조/위치·수치는 **HTML/SVG 벡터 도식**; 개념 예시는 실사에 가까운 생성 사진도 가능하지만 실제 실험으로 오해시키지 않는다.
- **스타일:** 기존 흰 배경·절제된 청회색/녹색·얇은 선·짧은 코너 라운드·넉넉한 여백을 유지. 밝은 유아용 클립아트, 과한 그라디언트, 게임풍 3D, 장식용 아이콘 남발 지양.
- **그림 내 텍스트:** 초보자 눈높이의 짧고 정확한 한국어를 사용. 영어 약어는 첫 등장에 Full Name + 뜻. Figure 내부에서는 같은 입력을 같은 색/기호로 추적하고, 점선/화살표 의미를 통일한다.
- **교실 기준 읽힘:** 1920×1080 설계 시 제목 약 36–48px, 본문 약 22–28px, Figure 레이블 약 18–22px을 목표로 한다. 실측 렌더에서 조절하며 무조건 전체를 축소해 맞추지 않는다.
- **반례/주의:** 기존 구성을 개선할 때 해당 슬라이드의 원본 데이터·수식 검산을 해치지 말 것. 설명 편의를 위해 임의의 Feature Map 값을 실제 모델의 출력인 듯 사용하지 말 것.

### 추천하는 공통 컬러 역할

- **사진/원본 입력:** 중립, 원본 색 유지.
- **선택한 Pixel·입력 영역:** 현재의 녹색 계열 강조.
- **Kernel/연산 영역:** 입력과 구별되는 일관된 청회색.
- **출력 Feature Map/판정 결과:** 통일된 녹색 또는 청록.
- **실패/미검출/오알람:** 과도한 경고색 대신 제한적인 대비색. 빨강/초록 **색만으로 정답 여부를 표시하지 말고** 텍스트·형태를 함께 둔다.
- 기존 CSS 전반을 다시 칠할 필요는 없음. **의미가 같은 요소가 강의 전반에서 같은 색**을 갖도록 조정.

## 3. 그림 유형별 기준

### A. 현상 설명용 실사/생성 이미지

한 대상의 조명·회전·크기·가림·흐림 비교에서 촬영 범위와 변환 종류를 표시하고 비교 이미지는 **동일한 크기와 대상 중심 위치**를 유지한다. 실제 카메라 촬영이 아니면 "화면상 변환"으로 구분. 작은 결함을 학습 목표로 제시했다면 결함 영역이 실제로 보이는 해상도인지 확인.

### B. CNN 아키텍처와 Tensor 구조

학술 발표 Figure처럼 전문적이되, 초보자는 한눈에 볼 수 있도록 **RGB 사진 → 여러 채널 Feature Map → 반복되는 Conv/ReLU → 크기 축소 → Head → 출력**의 계층을 나타낸다.

```text
 [사과 사진]   [여러 장의 반응 지도]   [더 깊은 반응 지도]    [분류 Head]
 H×W×3         H1×W1×C1              H2×W2×C2             정상/결함
      └────── Conv + ReLU ────── Stride/Pooling ──────→      (예시)
```

- Feature Map은 여러 **2D plane의 stack**으로 표현. "채널 수 증가"와 "공간 크기 감소"를 시각적으로 별개로 나타낸다.
- **CNN 구조는 원리 설명용 schematic**임을 명시. 실제 SqueezeNet 아키텍처라는 오해를 만들지 않는다.
- Conv/ReLU/Pooling을 매 CNN에 필수 고정 순서처럼 표시하지 않는다.
- 분류 Head 예시 뒤 C-21에서 검출/분할 Head로 분기. 같은 사과 입력으로 연결.
- 논문 Figure를 참고해 재구성하는 경우는 그림 자체를 직접 가져온 것이 아니므로 슬라이드에 참조용 출처 표기를 강제하지 않는다.

### C. 숫자·행렬·계산

- 같은 입력 예시(5×5 배열, 3×3 Kernel)를 C-12→C-13→C-16에서 일관되게 사용한다. C-17/18의 **다른 입력/Kernel 조건은 그림 위에 바뀐 이유**를 적는다.
- `행렬 전체 × 가중치 배열`이 아니라 **한 3×3 영역 × Kernel → 한 결과값**이 먼저. 선택한 숫자 9개에 1:1 연결선 또는 위치색 매칭.
- 결과 수치는 실제 HTML 값과 일치. ReLU는 가중합 결과에 별도로 적용하며, 음수가 생겼다는 이유만으로 원본 Feature Map이 잘못된 것처럼 표현하지 않는다.
- Stride = **다음 계산 시작 위치의 간격**, Padding = **바깥 값 추가**, Pooling = **정해진 영역 대표값 선택**. 셋을 모두 "이미지를 줄이는 필터"라고 묶지 않는다.
- 정확한 연산을 나타내야 한다면 임의의 이미지 생성보다는 SVG/HTML Canvas를 사용하고, 입력·출력 shape 및 모든 숫자를 검산한다.

### D. 평가/AI 작업 시각화

- **같은 사과 결함 100건**을 C-31→33→37에서 계속 사용. 정답 20개/정상80개, TP18/FN2/FP4/TN76이라는 숫자를 **같은 아이콘·색·순서**로 유지한다.
- C-37 Threshold에 따라 혼동행렬과 FN/FP가 즉시 바뀌는 **시각적 게이지/타일**이 표보다 먼저 눈에 들어오게 한다.
- C-35–39는 새로운 업무표 5장을 연속 보여주기보다 **사진·입력/출력 예시 → 한 장의 업무 흐름 → 결과·실패·검증**으로 돌아온다.
- **AI가 해준 일**과 **사람이 승인해야 하는 기준**을 두 칸으로 구분하되, 제품 Dashboard처럼 디자인하지 않는다.

## 5. 실제 이미지·논문 Figure 사용/출처 정책
