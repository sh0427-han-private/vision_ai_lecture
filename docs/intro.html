사람의 의미 인식 vs Pixel 숫자

같은 사과 사진을 보더라도 사람은 의미를 인식하고, 컴퓨터는 Pixel 숫자를 입력으로 받습니다.

사람의 인식이미지 → 의미
사람이 얻은 의미 · 사과

사진 속 대상의 의미를 바로 이해

컴퓨터·AI의 입력이미지 → Pixel 숫자
컴퓨터가 받은 입력 · 숫자 배열

Pixel 값에는 물체 이름이 없음

Vision AI가 어려운 이유: 숫자만으로는 의미가 주어지지 않습니다. AI는 다양한 Pixel 값 속에서 사과를 구별하는 공통 특징(Pattern)을 학습해야 합니다.

같은 사과 사진을 12 × 8 Grayscale 숫자로 변환하고 있습니다.

흑백 사진은 H × W 숫자 배열

Grayscale 이미지는 높이 H × 너비 W의 2축 배열입니다. 클릭하여 6 × 6개의 밝기 숫자를 확인해 보세요.

① 사진에서 영역 선택48 × 32 분석용 축소

사진을 불러오는 중입니다.

② Pixel 숫자6 × 6 행렬

한 칸 = 밝기를 나타내는 정수 1개

③ 숫자를 밝기로 표시동일한 36개 값

0 = 검정 · 255 = 흰색

원본 Pixel × 1.0 = 결과 Pixel

Grayscale 변환: Y = round(0.299R + 0.587G + 0.114B) · 밝기 조정: Y′ = min(255, round(k × Y))

한 Pixel에는 밝기 값 1개(8-bit 예시 0~255)가 있습니다. 원본을 48 × 32로 축소한 후 계산하며 H·W는 세로·가로 축입니다.

RGB · Pixel당 세 숫자

사진의 한 점을 클릭하여 [R,G,B] 세 숫자를 확인해 보세요. 각 값은 일반적인 8-bit 예시에서 0~255입니다.

사진 클릭 또는 방향키: Pixel 좌표 선택

이미지 전체 배열의 크기 불러오는 중 Height × Width × Channel · C=3 (RGB)

한 Pixel의 값: I(y, x) = [R(y, x), G(y, x), B(y, x)]

RGB 이미지 전체는 H × W × 3

높이 H=640 × 너비 W=960의 사진에서 각 Pixel에 R·G·B 세 값이 들어갑니다. 마지막 3은 공간 깊이가 아닌 Channel 축입니다.

640 × 960 × 3 = 1,843,200
614,400개 Pixel × RGB 값 3개 = 1,843,200개 숫자 데이터

동영상은 시간순 RGB 이미지 여러 장

동영상 파일을 디코딩하면 시간 순서가 있는 Frame(이미지)이 나옵니다. 각 Frame은 한 장의 RGB 사진입니다.

① RGB 이미지 한 장

[R,G,B] / Pixel
H × W × 3

② 시간에 따른 RGB Frame

시간 (time) →

각 Frame = H × W × 3

1초 30fps 중 대표 4장만 표시

③ Frame을 묶기

VideoT × H × W × 3

T = 시간순 Frame 수

RGB Image H × W × 3 → RGB Frames × T → Video T × H × W × 3

동영상은 RGB Frame 여러 장이 시간축 T를 따라 이어진 데이터입니다.

같은 사과의 이동은 교육용 시뮬레이션 · 영상 파일 압축 구조나 모든 모델의 실제 입력 Shape와는 다름 · 4차원은 배열 축 개수

다르게 생겨도 같은 종류

“사과인가?”와 “표면의 지정된 갈색 반점이 있나?”는 서로 다른 Label입니다.

객체 종류의 정답과 결함 판정 정답을 혼동하지 않습니다.

서로 다른 교육용 생성 사과 원본 2장 · 세 번째는 두 번째의 화면 밝기만 0.48배 · 타원은 교육용 주석

큰 변화보다 중요한 차이

정답의 기준은 갈색 반점 유무입니다. 밝기가 바뀌어도 Label을 유지하고 작은 지정 결함은 구분해야 합니다.

정답 \ 조건기준 밝기 ×1.0어둡게 ×0.48
정상반점 없음
불량반점 있음

큰 촬영 밝기 변화보다 작은 과제 관련 결함이 더 중요할 수 있습니다.

정상·불량은 서로 다른 생성 원본 · 각 원본에 동일 밝기 변환 적용 · 실제 촬영이나 실제 모델 출력 아님.
